# Proposed E06 loading contract — not canonical or accepted

Suggested home: frontend/chat-performance.md. Use actual completed checker recommendations and final current bytes before synchronization; this proposal is preparation only.

## 1. Scope / Trigger

Model/provider icons in the actual selected-model home picker and existing chat UI. Measure model-less home, selected home and plain/fenced history on the production-root router. Keep the existing complete rich renderer and identify its remaining library boundary separately.

## 2. Signatures / Owners

ModelIcons owns existing size-reserving Suspense. ModelIconCatalog reexports the demand adapter. DemandModelIcons owns ordered matching, one cached lazy component per publisher brand and exact variant selection. ModelIconMapping.generated owns data-only mapping and literal brand entry loaders. scripts/e06-icon-data.mjs owns deterministic AST extraction/checking from installed publisher source; no runtime vendor mutation. Native build/network/parity producers own actual root outputs and input fingerprints.

## 3. Contracts / Invariants

Preserve complete ordered case-insensitive regex model matching, exact case-insensitive provider matching, mapped props then caller prop precedence and default size/type. Unknown model and provider fallbacks remain distinct real publisher components. Preserve shape, class/style, mono/color/combine variants, exact lowercase lobehub color exception and forceMono. Internal render type is non-null after defaults and supported-type guard; do not broaden it merely to ignore switch exhaustiveness. Use actual publisher brand compounds and fallback precedence, not copies of SVG implementation or a restricted brand list. Version/renderer hashes and generated-data tests gate compatible upgrades.

## 4. Validation / Error Matrix

Missing model/provider uses its real default glyph. Known model/provider loads only selected publisher brand graph plus legitimately shared dependencies. Unsupported runtime type follows the existing default icon branch. Lazy load keeps existing size-reserving fallback. Variant checks include brands lacking optional Color/Combine/Brand/BrandColor/Text and preserved fallback order. Real code/plain/unknown fences, copy, links/table/math/diagram, reasoning/streaming, initial transcript loading and manual/pinned scroll retain existing behavior. Native errors fail; no paid provider requests.

## 5. Good / Base / Bad Cases

Good: preserve all source mappings and select before loading publisher compound entries. Base: selected-home actual cold unique JS body bytes decreased by 2,896,549 in the recorded one-sample comparison; no latency claim. Bad: importing the whole catalog to choose a model, narrowing mappings for a small demo, exact-string patching node_modules, or replacing Markdown with a lossy renderer to obtain smaller bytes. Plain-history highlighter loading remains explicitly measured and retained under current library module contracts, not described as eliminated.

## 6. Required Tests

Deterministic ordered AST/data equivalence and stale-generation rejection; actual publisher mapping/native render comparison for variants/fallback/props/geometry. Actual production-root baseline/current cold scenarios with identical seeds/producers/plugin/public/cache/font conditions; observed Rollup module graph and served-body hashes, unique/shared/exclusive asset accounting without cross-scenario double addition. Actual root rich/copy/loading/scroll parity with native Dexie notification and held requests. Current full/type/model/build and same-version static/value graph evidence align final current source. Type-only corrections may adopt original runtime proof only with actual emitted-asset byte equality and explicit current source attribution.

## 7. Wrong vs Correct / Attribution and Limits

Wrong: lazy syntax treated as proof of deferred payload, rendered module lengths called minified per-module allocations, downloaded body bytes called gzip/transfer latency, initial Tailwind discovery scope mixed with later isolated assemblies, regenerated routes described as unchanged. Correct: preserve actual source/config/imported-metadata closure and physical dependency bytes, exact served output bytes/status/timing separately, controlled source assemblies and scope limits, generated effective route bytes plus token equivalence and explicit exact opening restoration. Publisher es subpaths are physically present for the verified version and do not imply a long-term public subpath guarantee. Local Chromium one-sample measurements do not establish device performance or GitHub CI behavior. Sonar/type metrics and QG01 remain separate evidence owners.
