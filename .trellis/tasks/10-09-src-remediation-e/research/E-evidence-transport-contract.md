# Lossless E evidence transport

Original raw evidence remains in this working directory. The proposed documentation commit uses SHA256-keyed gzip blobs to avoid committing repeated native bundles/source copies/reports. The manifest preserves every captured original path, SHA256 and byte count; compressed blob index adds compressed SHA256/byte counts. Actual verification decompresses every unique blob and checks original hashes and bytes. Actual restore writes a new temporary root only; existing repositories/working directories are refused. Dependency/cache symlinks are documented, not followed or restored.

Copied publisher source evidence under research/e06/contract-primary-sources/node_modules is explicitly preserved. Actual build dist/.vite manifests are included. Installation node_modules and Python cache directories are excluded. No broad exclusion by folder naming overrides an accepted seal path. Independent accepted seal coverage must be zero-missing/zero-mismatch against the final manifest, not the preliminary inventory.

Permanent src/tests/scripts/quality/config are committed as readable normal files and do not depend on active/archive task paths. Small task PRD/design/context/research/check reports/producers and canonical/parent ledger files are also proposed as readable normal files. The blob transport preserves full immutable source snapshots/screenshots/served bodies/build graphs/failed-attempt records and raw reports, retaining paths via manifest and restore. No historical report, acceptance hash or raw failure is rewritten.

The pack cannot contain its own final receipt, transport review, or commit plan without recursion. Those late files remain normal readable files in the documentation commit. A completion receipt explicitly records their hashes alongside the frozen transport manifest. Final restoration/independent transport review is separate from whole-E source acceptance and is required before the concrete commit plan is approved.

Replay: from a repository checkout with normal saved tools/evidence-pack.py, run its verify mode on the saved evidence transport directory; use an explicit new --receipt path to keep prior receipts immutable. Restore mode requires --restore-root pointing to a new empty destination and restores the original repository-relative task paths. Use the restored copy to inspect individual original logs and images referenced in accepted snapshots. Install/test runtimes remain separate requirements.
