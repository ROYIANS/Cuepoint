# B03: partial configuration and set intent

Coordinator read-only preparation, 2026-09-30. B01 still active. Sources: ContextParameters, contextSettings, repo assertShotReferences/patchShot and ShotRow character UI, contextManagement tests, audit AU-03/PU-04.

## Context update
ContextParameters patch currently spreads the whole rendered normalized policy. updateContextPolicy currently normalizes and replaces without reading latest policy. Change the mutation to accept Partial<ContextPolicy> and merge with the transaction-read current normalized policy before normalize; UI passes changed fields directly. Reset-to-default and save-as-default are explicit whole-policy replacement operations: preserve their exact semantics (including removing optional customContextTokens when absent from the chosen source), not accidental merge preserving obsolete optional values. Either private full replacement helper or explicit replacement path is warranted; search callers first. Own global/general agent and thread existence logic remains transaction-scoped.
Independent fields must merge with no waiting for live query. Same-field ordinary setting follows last committed explicit intent (document/test); a complete reset explicitly replaces the whole policy in its transaction. Avoid adding revision infrastructure for settings switches.

## Character selection
ShotRow two callbacks are currently built from the same rendered shot.characterIds and each writes a full array. Keep patchShot array replacement for genuine full replacement (bulk assign/clear/other consumers) and add narrow intent mutation: explicit selected true/false for one character ID, applied to latest shot membership in transaction. Idempotent repeated add/remove; ordered existing set plus new IDs; retain unrelated edits/roles and project touch semantics. Validate shot, episode, project, and selected/current reference ownership using existing validators; do not let request supply a new owner. Invalid mixed owner operations must not partially alter row. Missing/deleted selection error; removal may be allowed for deleted formerly referenced target if it results in valid latest references—document actual choice. Use explicit selected checkbox value, not toggle-latest on delayed duplicate events. Rapid different adds/removes based on same render must commute correctly. No new configurable collection strategy framework.

Expected product scope: ContextParameters, contextSettings, repo, ShotEditorPage (after B01 reviewed). Tests: extend contextManagement/actual component callbacks plus focused actual IndexedDB character intent tests. Existing whole-array bulk undo A02 must remain exact replacement with atomic field baseline contract. Validate two independent stale context callbacks; optional field reset; invalid/missing scope; same-field last-commit behavior; rapid add/add, add/remove, duplicate intents, cross owner rejection and untouched media/other fields. Tests must call production mutations or actual UI callbacks, not mirror the merge.

Caller search confirms updateContextPolicy only ContextParameters + reset/save-default internals in src; tests use complete policies. normalizeContextPolicy drops undefined customContextTokens, so explicit patch `{customContextTokens: undefined}` can clear it when spread over latest. Full replacement reset/save-default must still remove optional field absent from chosen source; ordinary partial policy merge cannot implement reset semantics alone. Existing bounded integer normalization remains unchanged.
