# B02: memory promotion session contract

Coordinator preparation, 2026-09-30. Read actual MemoryPromotion, TaskWrapup, MemoryEditor and project-memory spec. B01 is still in progress; this is preparation only.

## Confirmed chain
Each MemoryPromotion owns pending and directly calls listMemoryCandidates. ReviewDocument forwards the shared TaskWrapup onCandidate callback to every decision/lesson, including history. TaskWrapup passes setCandidate unconditionally in current and historical documents. A second completed request replaces candidate after MemoryEditor has mounted; editor baseline/source/excerpt remain render-prop derived while draft/tags only initialize once. Actual source promotion uses current source and previous draft.

## Minimal correction
Centralize source request ownership in TaskWrapup (or one bounded helper with actual consumer), synchronously acquire a ref lock before awaiting; UI pending is display-only. ReviewDocument/MemoryPromotion submit a MemorySourceRef intention; parent does the read/selection and publishes only if its captured task/project session and request epoch still match, no editor is already open, and component is mounted. Disable all candidate buttons while shared preparing/editing (including history); immediate rapid callbacks must still be ref-guarded. On failure release lock, toast bounded existing message and allow retry; closing/saving invalidates old requests and releases editing state explicitly. Candidate/editor must be one frozen snapshot: cloned input/ref/excerpt, stable editing session identity, expectedRevision and owner. MemoryEditor itself should initialize frozen initial/baseline/source/sourceExcerpt from a single mount session for all create/edit paths; subsequent props cannot rebind a dirty draft. Preserve existing live revision reconciliation and blockers. If an owner/memory/source identity change is possible through same mounted instance, reject mismatched writes and keep draft instead of writing new target; normal callers use proper identity lifecycle.

No blindly added candidate key that discards dirty editor; no repository/source validation weakening. Existing owner/revision/confirmed source validation stays in projectMemories.

## Scope and regression
Expected three product files: MemoryPromotion, TaskWrapup, MemoryEditor. Optional narrow shared session helper only if actual fixture/ownership needs justify; search existing lock/session patterns first. No A04 slot/output/identity modifications, no later E01 TaskWrapup summary dirty-exit changes.
Runtime tests execute actual parent/button/editor callbacks, not just helper or copied logic. Drive two rapid source requests before rerender; prove parent lock avoids concurrent publication or token makes both completion orders safe; completing an older request after editor opens/closes/reopens/unmount/task switch cannot replace active session. Assert one coherent body/ref/excerpt reaches promoteProjectMemory; dirty remains with live query refresh; failure releases request lock and retries, pending state reports to inspector; saving/dirty route protection remains. Real DB candidate validation existing tests supplement UI callback regressions, not replace them. Clearly distinguish lightweight hook-host from real DOM/router scheduling.

Additional verified boundary: TaskInspector wraps TaskInspectorContent with key=task.id, and TaskWrapup is inside it. Current task replacement normally remounts TaskWrapup; no B02 need to redesign inspector ownership. Async candidate request unmount must still invalidate publication/toast/state. Parent callback/pending lock must be shared across both latest and history ReviewDocument calls, not just latest. MemoryEditor ordinary project-memory callers already use editor identity; freeze initial/source/owner/expected revision as one session and keep explicit latest reconciliation separate.
