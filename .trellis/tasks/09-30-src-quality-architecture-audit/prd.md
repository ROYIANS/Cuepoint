# src 全量代码质量与架构审查

## 目标
逐文件审查 src 的实现质量及目录、模块职责，确认类型与控制流、遗留冗余、依赖边界、重复实现、抽象和业务规则分散的问题，形成可核验的整改依据。

## 范围
- 全部 Git 跟踪的 src 文件，包含 CSS、类型声明和生成文件；生成文件核验来源、生成链和接入。
- vendor 不纳入；tests 不做逐文件审查，仅作为行为和回归依据；项目配置作为工具与边界分析背景。
- 本轮交付审查与整改建议，不改变产品行为，不修复产品源码。可使用独立分析工具，不把分析依赖加入产品依赖。

## 验收
- 每个范围内文件在覆盖清单中有工具扫描/阅读状态与结论；未覆盖、解析失败和工具局限明确记录。
- 每个确认的问题含文件位置、具体机制、影响、严重程度、建议及验证方式，区分结构债务与已证明行为缺陷。
- 目录结构审查包含当前依赖关系、循环依赖、职责归属以及逐步迁移方案；文件大小本身不构成违规。
- 核验重复行为和多处业务规则，避免仅依据相似文本合并不同契约。
- 记录实际执行的工具、版本、命令、退出状态及原始结果。
- 保持 src 与审查基准内容一致；不自动提交或推送。
