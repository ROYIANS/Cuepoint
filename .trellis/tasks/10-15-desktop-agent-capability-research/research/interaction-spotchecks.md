# 项目与素材界面的交互抽样

调查日期：2026-10-15。基线为 Cuepoint `9d1a41739b17be27cf832326de15a9489017825a`。这是在 Agent 交互审计之外，对项目列表、世界资产列表和素材导入三个入口的有限源码抽样；不是全站视觉或性能验收。`features/`、`ui/` 路径相对 Cuepoint 的 `packages/studio/src/`，`.trellis/` 路径相对仓库根目录。

## 已确认：相同操作的反馈标准不一致

项目创建在 `features/projects/ui/ProjectGalleryPage.tsx:112` 先锁定重复提交、设置 `submitting`，再等待 repository；失败保留弹窗和原值并显示错误。重命名、删除也有对应 pending/error 状态（`:135`、`:154`）。素材导入有同步 `pendingRef`、明确进行状态和剩余队列（`features/library/ui/materials/MaterialImportDialog.tsx:31`）。这些现有实现可以作为统一交互的起点。

相邻的世界资产界面却没有同样的保证，说明问题不只是一个慢请求，也包括异步操作缺少共同的交互约定。

## 应保留的正确行为

- 项目创建、重命名、删除与绑定操作有请求前的 busy 状态、重复点击保护和错误恢复；不用为实现乐观 UI 放弃这些保障。
- 素材导入每确认保存一项后才移除该项，失败保留未完成队列。这比整批清空再从头重试更符合实际副作用。
- 项目封面查询携带 scope key，旧结果不匹配时不展示（`ProjectGalleryPage.tsx:106`–`:110`）。这种结果归属机制值得在异步页面切换中统一。
- 删除会清理实体引用和孤儿媒体（`features/library/commands/assets.ts:65`），其业务效果仍要由产品事务确认。乐观呈现不等于提前写入 durable success。

## 建议形成的交互约定

1. **用户意图先得到反馈。** 点击后立即有可见状态；不要求已成功，也不必等待本地数据库或原生 IPC 才显示正在处理。
2. **同一提交有一个 identity。** 重复点击、渲染更新和超时重试不会意外变成多个创建动作；允许用户有意创建多个资产要有明确的独立操作。
3. **失败留在操作附近。** 用户能看到失败目标、保留的输入和恢复动作；不能只依赖控制台或全页错误。
4. **加载、空、失败、陈旧结果分开。** 缓存值用于避免闪烁时，仍要核对 scope 和呈现当前读取状态。
5. **进度对应真实阶段。** 显示已完成项、当前阶段和可取消范围；不编造百分比或承诺撤销已经提交的效果。

这些是从抽样得出的候选规范，不是已批准的全站重构。尚未测量真实 IPC 延迟、浏览器绘制或用户操作轨迹；以上建议应使用相应的真实 UI 与延迟/故障注入验收。
