# Research: MCP product integration and immutable execution

- Query: Find the actual Studio/core/native seams for adding desktop MCP tools/resources without duplicating permission, execution or retained-result owners.
- Scope: internal; protocol/SDK and OAuth implementation choice is separately researched.
- Date: 2026-10-16

## Findings

### Recommendation

Keep the existing Agent loop and ProductStore. Add one device-local MCP connection owner, one finite host-service port, and a Studio adapter which turns a **frozen connected-server generation** into ordinary `AgentToolDefinition` values and capability groups. Desktop macOS/Windows must support both stdio and Streamable HTTP, including manual credentials and OAuth. Web can implement the same remote port when endpoint/browser capabilities permit; no proxy/backend or browser parity prerequisite belongs in desktop delivery.

Connection/discovery is a user configuration workflow, not an Agent background worker. A text skill cannot install/enable a server or grant its credentials. No particular live service/account is required: deterministic local stdio and HTTP/OAuth fixtures can prove the contracts.

### Proposed data contracts

Names are design suggestions; settle their spelling in `design.md` before implementation.

1. **`McpServerConfig`**: device-local stable `serverId`, safe user label, monotonically checked `configRevision`, enabled flag, transport-specific config, and auth mode. For stdio keep executable/argument vector/cwd/environment secret references user-authored and outside model context. For remote keep normalized endpoint plus a credential reference, not token-bearing URLs. General model-provider connectors remain unchanged.
2. **`McpConnectedGeneration`**: `{serverId, configRevision, binding: {capabilityId, version, registrationId}, manifestRevision, tools, resourceCapabilities}`. `version` represents immutable normalized manifest identity; `registrationId` is freshly host-issued for every connection/catalogue generation and never reused. Host session/workspace generation is additionally checked at IPC effects. Namespaces use a bounded stable server/tool mapping, e.g. a safe opaque server component and digest; freeze the original server tool name mapping, reject collisions, never retarget by display name or array position.
3. **`McpRunSnapshot`**: bounded, secret-free server identity, namespace map, validated schemas, safe labels/descriptions, groups and capability binding, copied at admission. Save it as an optional versioned `AgentRun` field. Conversation mode has no MCP names/snapshot. Retry/preview/resume use this saved snapshot; legacy runs acquire nothing from today's servers. A new send can select a new generation.
4. **`McpPreparedAuthority`**: host-issued `ResourceGrantSnapshot<McpInvocationFact>` bound to `{runId, callId, scopeId}`, exact generation/config/manifest, original tool name or discovered resource identity, argument digest and permission/config revision. Expose only bounded display facts in `AgentToolPreview`; retain exact authority in a typed `mcp` preview member with validation. The service consumes/rechecks authority and current connection under its own ownership immediately before IO. A renderer passing strings/IDs alone is insufficient proof.
5. **`McpInvocationEnvelope`**: finite action plus original operation ID, current host session, binding/authority and immutable run/call association. Host returns closed statuses such as `not_started`, `completed`, `failed_response`, `unknown`; malformed/lost replies after possible send remain unknown. Record dispatch disposition, protocol request identity and safe response metadata, never credentials. Retry transport status/readback by the original ID is distinct from repeating `tools/call`.
6. **`AgentJobSelection` MCP variant**: exact original local call name, server/binding, operation (`tool`/`resource_read`), target and argument revision, selected count 1. Extend job metadata with a finite MCP source descriptor. Keep **non-atomic external effect + atomic local publication**: no HTTP/process IO inside a store transaction, and no `atomic`/`repeatable` recovery flag for external work. Ensure validation, clear, recovery, ownership and UI switch statements handle the variant explicitly.

The SDK host/OAuth researcher should select transport and credential persistence. Regardless of SDK language, keep this product-facing port neutral and finite; no Node worker, Cordis framework, second Agent loop or backend is required by these contracts.

### Admission → preview → effect → resume flow

1. User configures/connects a server. Host validates config, starts/connects the transport, negotiates and gathers a bounded paginated catalogue, validates schemas, freezes normalized discovery and registers one generation. Connecting is user initiated; startup may restore configuration but must not execute model-suggested processes or replay old calls.
2. A new send captures eligible connected generations and combines their groups with built-ins **before** finalizing allowed names, discovery instructions and context budgets. Use the same pure composer for new-context preview; admission additionally checks/persists the exact capture through its original transaction. Do not await network discovery inside ProductStore transactions. Recheck the captured generation after any asynchronous preparation; stale capture fails safely or is omitted according to an explicit availability contract, never silently substituted.
3. `executeChatRun`/`resumeChatRun` materialize the registry from the saved run's exact snapshot plus `BUILTIN_TOOLS`. Closures capture exact generation services and verify them on prepare and execute; never resolve a call against the currently selected display-name server. Do not make a mutable global array the per-run registry.
4. Core freezes each request's offered definitions. Studio uses **that argument** for both schema wire request and corresponding context budgeting; `startModelStep` persists its exact offered names. `saveToolRound` explicitly persists binding. Invalid/unoffered names remain already-failed calls with a bounded model result and zero external dispatch.
5. Tool prepare validates arguments with the compiled untrusted-schema validator and host-issued resource authority, writes a bounded plain-text preview, and goes through existing `requiresToolApproval`. Treat server risk/idempotency annotations as informational, not permission. A conservative initial tool policy is host-owned `effect: network`, `highRisk: true`, non-atomic, no recovery marker; ask/assist gate it and full follows the existing explicit full-mode policy. Do not silently force another unrelated permission system. Host-defined resource read/list policies can be separately lower risk only when their exact operation/target is known.
6. At final claim recheck saved binding/preview/arguments and ProductStore ownership. At actual native/remote dispatch independently recheck active generation/authority/current credentials. This closes revocation/replacement during approval, async validation or the gap after the transaction claim. No remote effect can be made atomic with a local store transaction; document this boundary.
7. After acknowledged E07 admission/start, invoke once. Publish bounded untrusted text/structured JSON through the existing chunk/result transaction, then return the small original result descriptor when the effect outcome is established. Extend publication's call-status contract explicitly: retained evidence of an unknown MCP effect keeps the originating call `unknown`, rather than unconditional `completed`; the shared loop must still block continuation/replay. Known protocol failure responses can be recorded truthfully without claiming no side effects; lost responses, cancellation after dispatch or unreadable completion remain unknown and block automatic replay. Preserve locally acknowledged result before propagating abort.
8. Stop cancels the protocol wait and sends protocol cancellation where available; report external effects may continue. Disconnect first retires registry generation and rejects new dispatch, then drains/cancels pending IO and cleans up the owned process/HTTP/OAuth resources. Readback of retained results does not need the server online.
9. Reconnect, config replacement, uninstall and incompatible tool-list change issue a new generation. Existing pending approvals may still be rejected/ended, but cannot execute against a replacement. After application/host restart, old ephemeral registrations are not revived merely from saved metadata. Successful same-identity token refresh need not replace manifest identity; changed account/issuer/scope must not broaden an approved connection. Confirm the exact identity rule in OAuth design.

### More tools than one group can hold

Do not place an entire arbitrary server into one capability group and hope the 36-tool cap catches it: a server with 80 tools would become undiscoverable/unloadable. Do not bypass advertised schemas with an all-powerful `mcp_call(name,args)` gateway.

- Freeze sorted server tool definitions at run admission and partition them into deterministic, bounded subgroups, whose stable IDs include server/manifest/chunk identity. A chunk fits `36 - foundationToolCount`; count selected resource helpers and `read_job_result` wherever actually offered. Compute from the run's real foundation (including task and installed-skill helpers), not a hardcoded current count.
- Keep existing at-most-two **requested** groups and exact total-name cap. Two chunks/built-in combinations that exceed 36 fail with actionable selection guidance; one compatible chunk still works. Pending calls remain pinned and can make an otherwise valid new chunk temporarily unavailable. Do not reduce the permission ceiling when evicting a discovery group.
- Specify finite server/catalogue/schema/description/total-byte limits in design. Chunking alone does not bound initial catalogue instructions, normalized schemas or persisted run snapshots. Server pagination must detect repeated cursors and stop at those bounds; oversized catalogue/schema must be explicitly rejected or expose a clearly disclosed bounded selection, never silently claim complete discovery.
- A single schema/tool too large for the model/request budget is unsupported with a named reason. Dividing tool names does not fix an oversized parameter schema. Build groups deterministically from the immutable capture; do not fetch another list during `load_tool_groups`.

### Resources and retained UI

Treat discovered resource metadata/content as untrusted input. Offer finite per-server resource-list/read wrappers under the same generation and group budget. Prefer host-issued opaque resource handles from bounded discovery; bind concrete URI/template expansion to discovered metadata and preview rather than giving arbitrary URLs/files implicit authority. Content can flow into E07 retained text/JSON reports; first delivery can explicitly report unsupported binary payload kinds or link descriptors without falsely claiming the model saw images/audio. Do not inject every resource into the system prompt or automatically dereference links returned by tools.

Reuse the current right `ContextPanelHost` for connection management/report detail as appropriate; chat remains mounted. Narrow views retain the approved full-width workspace switch. Settings own persistent server configuration/credentials; Agent management owns run capability visibility and links into that configuration. Quiet normal success, immediate local control response, uncertain intent retention and actionable recovery follow existing UI specs. Do not create an MCP drawer or new transient "preparing/confirming" captions.

Device configuration/credential material never enters project exports, agent request JSON, run snapshots, tool arguments, trace breadcrumbs or error strings. Saved external **results** can contain user service data, so preserve existing thread/project scoping and explicit clearing. Verify actual serializers rather than assuming device-key naming excludes secrets. Product archive/export ownership remains `app/workflows/packages/projectPackage.ts` and the actual feature package codecs; this investigation did not establish a new export format.

### Minimal meaningful validation

Do not run every historical suite or app/package build at every stage. Add tests which would fail if the actual safety boundary were removed:

1. **Real composition/offer:** new run and matching preview capture the same server generation/names; conversation/legacy retry do not gain MCP; >one-group catalogue partitions with actual foundation helpers; two-group overflow fails; `load_tool_groups` takes effect on the next request and same-round never-offered external name causes zero dispatch. Extend `tests/toolLoading.test.ts` and `tests/agentRuns.test.ts`, not only a standalone mapper test.
2. **Approval and replacement race:** actual ProductStore + production runChat/core loop, block at prepare/approval/final claim; disconnect/reconnect/config/tool-list replacement between each barrier; original call cannot hit new server even when names/schema match. Include binding in persisted call, transactional fingerprint and job envelope. Existing `tests/agentRuntimeClaimRaces.test.ts` is the pattern.
3. **Exactly one external invocation:** deterministic fixture acknowledges a side effect then loses response; Stop/reload/explicit resume/refresh reconnect never call it again. A retained unknown report must not turn its original external call into `completed` or unblock continuation. Unknown admission/publication acknowledgements reconcile original retained completion without effect replay. Exercise actual E07 publication/clear/readback and cross-thread refusal (`tests/agentJobs.test.ts`), plus oversized/malformed output.
4. **Host lifetime:** real fixture child for stdio handshake/list/call/cancellation/close, stdout bounds and stderr redaction, owned-process cleanup on disconnect/host close; HTTP fixture covers session identity and redirects, disconnected/stale operation IDs, current credentials and aborted waits. Windows process-tree lifecycle requires its own target-platform evidence; passing Rust logic on macOS is not installed Windows proof.
5. **Auth and management:** deterministic OAuth fixture proves stale/wrong-state/wrong-server callback rejection, cancellation, refresh under the same identity and disconnect cleanup; login/refresh does not replay a tool. Real UI control retains unknown edits/reopens and keeps Agent mounted; no credential in captured model wire/diagnostics/actual project serializer. Test browser compatible and unsupported endpoints without building a proxy.

Run only these affected test files, package/source type profile, scoped lint and relevant native module tests when implemented. When a running Vite consumes a changed reusable-library export, explicitly regenerate those dependency artifacts and check actual emitted/runtime exports; this is distinct from deferred whole-app builds/installers. This research ran no tests/builds/installations and claims no protocol compatibility pass.

## Caveats / Not Found

- No production general MCP service, concrete E06 ResourceGrantPort installation, general OS credential store or existing OAuth callback owner was found by these source searches. Core contracts and a generic external-link opener are not implementations of those components.
- Process host/SDK, secret-store choice, executable/environment validation, concrete numerical catalogue/schema limits, exact remote auth identity rule and unsupported optional MCP features still need the final technical design. These are engineering decisions within the confirmed scope, not reasons to ask the user the resolved transport/platform questions again.
- An SDK cancel or closed child IO does not prove cancellation of external effects or descendants; actual process-tree ownership and protocol outcome evidence are distinct.
- MCP response/annotation metadata cannot establish idempotence, local rollback, trusted instructions, output pixel access or durable paid-operation recovery. Retain truthful unknown status.
- Project export serializers were identified but not comprehensively audited in this bounded investigation. Plan an executable secret-exclusion assertion on the actual final serialized bytes.
