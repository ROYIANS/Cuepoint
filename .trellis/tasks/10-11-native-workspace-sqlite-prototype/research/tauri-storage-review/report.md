## Findings (fixed)

### A-F1 — Backup could publish corrupt copied closure

- File: `desktop/tauri/src-tauri/src/backup.rs`.
- Trigger: change a destination asset after copy at `backup-before-completion`.
- Mechanism/impact: only source-copy hashing and the earlier DB hash were checked; completion still returned success although restoring the result failed.
- Fix: extract the strict snapshot verifier, recheck destination DB hash/size/schema/integrity/UUID/pending-state/record closure and every copied asset type/size/hash after the completion hook; then validate source boundary/lifecycle/cancel immediately before exclusive manifest publication.
- Regression: `backup_rejects_destination_bytes_changed_before_completion`; prior source exit101 retained in `adversarial-first-failing.log`, current source passes and has no completion marker on failure.

### A-F2 — Restore could mark a corrupted target ready

- File: `desktop/tauri/src-tauri/src/backup.rs`.
- Trigger: change a copied target asset at `restore-before-completion`.
- Mechanism/impact: earlier source-copy and DB validation did not recheck the target at readiness; restore returned an opened workspace with corrupt bytes.
- Fix: reuse the same strict snapshot verifier after the hook and before ready publication. Failed reserved roots retain their bytes and have no ready marker; create/open cannot silently reuse them.
- Regression: `restore_rechecks_copied_target_before_ready_marker`; prior exit101 in `restore-target-first.log`, current passes.

### A-F3 — Unknown explicit index bypassed versioned schema validation

- File: `desktop/tauri/src-tauri/src/database.rs`.
- Trigger: add `CREATE UNIQUE INDEX unexpected_title ON projects(title)` to an otherwise valid DB.
- Mechanism/impact: exact table SQL plus trigger/view checks accepted an index that changes write behavior.
- Fix: reject explicit indices with non-null SQL; SQLite autoindices implied by exact table definitions remain allowed.
- Regression: `strict_snapshot_rejects_unknown_index_and_duplicate_manifest_keys`; prior exit101 in `adversarial-first-failing.log`, current passes. Duplicate manifest keys also reject before destination reservation.

### A-F4 — DB auxiliary links were checked only at connection setup

- Files: `desktop/tauri/src-tauri/src/database.rs`, `workspace.rs`.
- Trigger: add a hard-linked metadata journal after the owner is open, before SaveProject.
- Mechanism/impact: the operation accepted static unsafe auxiliary state. The observed host SQLite preserved the external target; **no external-byte corruption was observed or claimed**.
- Fix: share ordinary-file/link validation for DB/journal/WAL/SHM and run it at every boundary validation, including operation admission and actual COMMIT.
- Regression: `journal_alias_added_after_open_cannot_modify_external_file`; prior exit101 in `journal-alias-first.log`, current passes and external bytes stay unchanged.

### A-F5 — Concurrent idempotent close returned before writer release

- File: `desktop/tauri/src-tauri/src/worker.rs`.
- Trigger: block a committed import at postcommit, start close, then call close again.
- Mechanism/impact: the second caller returned Ok from the already-set atomic flag while the first caller still waited for the held writer/thread. Immediate reopen could fail.
- Fix: private close-serialization mutex makes every successful caller wait for the actual close/join barrier. Committed import still returns success.
- Regression: `every_close_caller_waits_until_writer_is_released`; prior exit101 in `concurrent-close-first.log`, current passes.

### A-F6 — Submit/close race retained nonexistent cancelable operations

- File: `desktop/tauri/src-tauri/src/worker.rs`.
- Trigger: 16 simultaneous submit callers race close; test checks up to 32 iterations.
- Mechanism/impact: a Run admitted before the atomic close flag could be sent after Close, never executed, leaving an operation entry whose wait ended but cancel still returned true after lifecycle completion. The prior source reproduced this immediately.
- Fix: the existing registry mutex also serializes admission: submit checks lifecycle/registers/sends Run under it; close sets lifecycle and sends Close under it, releasing it before waiting. All admitted earlier jobs are processed or rejected and removed before close completes.
- Regression: `submit_close_race_never_leaves_completed_operations_cancelable`; prior exit101 in `submit-close-first.log`, current passes. This finite concurrency regression supplements the inspected lock ordering; it is not a claim about every scheduler interleaving.

### A-F7 — Publisher could emit completion JSON its own reader rejected

- File: `desktop/tauri/src-tauri/src/paths.rs`.
- Trigger: individually bounded text fields collectively exceed the existing 16 MiB manifest reader budget.
- Mechanism/impact: serialization had no output cap, so publication could succeed for an unrestorable manifest.
- Fix: stream-count writes under the same MAX_MANIFEST_BYTES budget, return focused size error on overflow and never publish the completion name. Incomplete task-owned temporary bytes remain; there is no media-sized/full excessive JSON buffer.
- Regression: `completion_publication_cannot_exceed_its_reader_boundary`; prior exit101 in `manifest-boundary-first.log`, current rejects overflow and proves exact-budget JSON publishes and reads successfully.
