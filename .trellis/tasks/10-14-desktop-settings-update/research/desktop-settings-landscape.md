# Research: 桌面端设置页与版本更新现状调研

- **Query**: 为 Cuepoint 桌面端新增设置页（通用/外观/存储/关于与更新）+ 版本更新（检查、应用内下载安装包、打开发布页）的现状与约束
- **Scope**: mixed（内部为主）
- **Date**: 2026-10-14
- 说明：本机无 Rust，以下 Rust 侧结论均为读码所得，未编译验证。

## 1. 前端壳与路由

### 事实
- 桌面端与 web **共用根目录 `src/`**。桌面 UI 脚本 `desktop/tauri/ui/*` 仅是 bridge/验收；`desktop/tauri/scripts/build-frontend-worker.mjs:20` 用同一份 `src/` 打包，并注入 `__APP_VERSION__`（取自 `desktop/tauri/package.json` version）。`desktop/src`、`desktop/renderer` 是旧 Electron 原型，与本任务无关。
- 路由：TanStack file routes，`src/routes/_studio.*.tsx`，布局 `src/routes/_studio.tsx` -> `StudioShell` -> `AppFrame`。生成文件 `src/routeTree.gen.ts`（新增路由文件需重新生成）。
- **现有 `/settings` 仅为重定向**：`src/routes/_studio.settings.tsx` `beforeLoad: throw redirect({to:"/about", replace:true})`。`/about` 页是 `src/components/studio/AboutPage.tsx`（Logo、GitHub 链接、赞赏、数据与隐私文案；用 `PageContent mode="document"` + `PageHeader`）。
- 侧栏导航 `src/components/layout/AppFrame.tsx` 的 `NAV`：最后一项 `{to:"/settings", label:"设置", active: matchesPath("/settings")||matchesPath("/about")}`（index 6 为 `app-nav-utility-first`）。顶栏品牌 Logo 链接到 `/about`。
- 模块内二级导航：`src/components/layout/ModuleLayout.tsx`（`navigation` 插槽，默认 260px，`aside.module-navigation`；窄屏 <768 变左侧 overlay，含焦点陷阱）；样式类 `module-nav-heading/module-nav-group/module-nav-item`（用法见 `src/components/studio/StudioShell.tsx` 素材库）。`StudioShell` 仅对素材路由套 ModuleLayout，设置路由需自行在页面内或 StudioShell 中套一层。
- **无现有偏好/主题/语言存储**：`index.html:2` 写死 `<html lang="zh-CN" class="dark">`；无 theme provider、无 i18n；`localStorage` 仅用于 landing（`src/landing/download/releases.ts` 缓存）、`topicGrouping.ts`、`FloatingComposer.tsx`、`SkipButton/mode.ts`。`src/db/database.ts` 无 settings/preferences 表。产品数据在桌面是 SQLite（ProductStore），浏览器是 IndexedDB。
- 无 "Back to app" 现成组件；`PageHeader` 有 `back` 插槽（`src/components/layout/PageLayout.tsx`），`icons.tsx` 有 `ArrowLeft/Search/Folder/FolderOpen/Download/ExternalLink/RefreshCw`。无 Switch 组件（`src/components/ui/` 有 alert-dialog badge button checkbox dialog dropdown-menu field input label popover select sheet slider tabs textarea tooltip sonner）。
- 可复用 token（`src/styles.css`）：`--surface-chrome #242424`、`--surface-app #101010`、`--surface-panel #151515`（= `--card`）、`--surface-elevated #202020`、`--muted/--muted-foreground/--border/--brand`；Tailwind 色 `bg-card / text-muted-foreground / border`。规范要求：h1 24px/600/32px，正文 14/22，元数据 12/18；"restrained neutral grouping，避免嵌套卡片与装饰色条"（`.trellis/spec/frontend/desktop-ui.md` §3）。
- 参考页：`src/components/studio/ConnectorsPage.tsx`（"连接与模型"）可作为表单/行布局参考；已有 `Dialog/AlertDialog/Select/Tabs/Input`。

### CSP（tauri.conf.json）
`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; media-src 'self' blob: http://127.0.0.1:*; worker-src 'self' blob:; font-src 'self' data:; connect-src ipc: http://ipc.localhost 'self'; object-src 'none'; frame-src 'none'; base-uri 'none'`
- `connect-src` 不含 api.github.com / github.com：WebView 原生 `fetch` 到 GitHub 会被 CSP 拒绝。外网请求现靠 `tauri-plugin-http`（绕过 WebView CORS/CSP，但受应用策略约束）。**规范明确：不得 "globally widen fetch/CSP"**（`native-product-runtime.md:328`）。

### 现有命令（均 `trusted(&window)?` 校验 main 窗口）
`workspace_request, product_store_request, product_binary_request/read/write, product_media_preview/release, workspace_cancel, authorize_http_origin, product_save_begin/chunk/finish/cancel, product_print_storyboard, product_open_external`（acceptance 特性另有 `acceptance_request`）。
- **无**获取版本/数据目录/磁盘占用/打开目录/下载文件的命令。

### Cargo.toml 已有依赖（`=` 精确锁版本，`--locked`）
`rusqlite 0.40.2(bundled,backup)`, `serde`, `serde_json`, `sha2 0.11.0`, `uuid`, `tauri =2.12.2`, `tauri-plugin-dialog =2.8.1`, `tauri-plugin-http =2.8.2`（vendored 补丁，`vendor/tauri-plugin-http`；features rustls-tls/http2/charset/system-proxy）, `tauri-plugin-opener =2.5.4 (default-features=false)`, macOS 下 objc2*。**无直接 `reqwest` 依赖**（只经 tauri-plugin-http 间接带入；Cargo.toml 无 `reqwest`），无 shell/fs/updater 插件。`tauri-plugin-http` 保持间接 reqwest 可用但直接 `use reqwest` 需新增依赖条目并更新 Cargo.lock。
- Cargo.toml 中 `sha2` 已存在，Rust 侧算 sha256 无新依赖。

### 打开外链 / 文件夹
- 外链：前端 `nativeOpenExternalUrl`（`src/lib/nativeSystemServices.ts` 末尾）-> `product_open_external` -> `window.opener().open_url(...)`；仅 http/https、无 userinfo、≤8192 字节。`src/lib/runtimeExternalLinks.ts` 全局拦截 `<a href>` 外链并走此命令（`<a target=_blank>` 在桌面端自动走系统浏览器）。opener 插件 `.open_js_links_on_click(false)`；opener 的 JS 权限**未**授予（capability 无 `opener:*`）。
- 打开文件夹/文件：**现无**。`OpenerExt` 在 `runtime_services.rs` 已 import，API 有 `open_path(path, with)` 与 `reveal_item_in_dir(path)`（opener 2.x 提供；本机未验证签名），但需新增自有 Tauri 命令，Rust 侧选路径（不接受渲染端路径），并同步 build.rs 两份命令列表、`desktop.rs` 两份 `generate_handler!`、`capabilities/main.json`、`permissions/autogenerated/*.toml`（后者由 build 生成，但提交在库内）。
- 规范（`native-product-runtime.md:257`）：“raw file/custom-scheme opening and broader main-window navigation are not enabled”。

### 桌面存储（“存储”分区可展示）
- 根：`app.path().app_data_dir()`（由 identifier `dev.cuepoint.prototype.offline` 决定；macOS `~/Library/Application Support/dev.cuepoint.prototype.offline`，Windows `%APPDATA%\dev.cuepoint.prototype.offline`，Linux `~/.local/share/dev.cuepoint.prototype.offline`——推断自 Tauri 约定，未实测）。
- 正常产品（product-sqlite）：`<app_data>/product-workspace-v1/`（`desktop.rs` ~60-80）；内含 `metadata.sqlite`、`writer.sqlite`、托管媒体文件（`workspace.rs:715-837`）。验收/原型另有 `<app_data>/workspace`（`desktop.rs:~1030`）。非 macOS 的 WebView 数据目录 `<app_data>/webview-profiles-v1/<32hex>`（`runtime_services.rs:19-37`）；macOS 用 `data_store_identifier`。
- 可展示信息：数据目录路径（Rust 可返回字符串，当前渲染端拿不到）、目录总大小（需新增 Rust 遍历；注意规范对符号链接/reparse point 严格，`paths.rs`）、打开目录（需新命令）。前端侧能不新增 Rust 得到的：`navigator.storage.estimate()`（桌面 SQLite 下无意义）、项目/素材计数（走 ProductStore 查询）。**数据目录为只读展示；规范强调“不要把数据目录移到网盘/不要在运行中替换 SQLite”**。

## 3. 下载安装包方案对比

### 可复用的现有前端代码（`src/landing/download/`）
- `releases.ts`：`fetchLatestDesktopRelease(deps)` 已含：GitHub API `https://api.github.com/repos/ROYIANS/Cuepoint/releases?per_page=30`（未鉴权，8s 超时，6h localStorage 缓存），过滤 `draft` 与 tag 正则 `^desktop-v(\d+)\.(\d+)\.(\d+)$`，按 semver 降序取最新，**包含 prerelease**；`isUnder()` 规范化后校验 `browser_download_url` 以 `https://github.com/ROYIANS/Cuepoint/releases/download/` 开头（防 `../../`），`html_url` 校验；`digest` 字段 `sha256:<64hex>` -> `asset.sha256`；`ReleaseAsset={name,size,url,sha256?}`；全部依赖可注入（`fetchImpl/now/storage/signal`），可直接传入 `runtimeFetchFor(...)` 复用。`fetchStars` 与本任务无关。
- `platform.ts`：`pickAssets(release, platform)` 与资产名正则 `^Cuepoint_(\d+\.\d+\.\d+)_(macos_arm64\.dmg|macos_x64\.dmg|windows_x64_setup\.exe|linux_x64\.AppImage|linux_x64\.deb)$`（与 `desktop/tauri/scripts/release-policy.mjs:19-24` `assetName()` 一致），且要求文件名内版本 = tag 版本；Linux 默认选 AppImage，deb 备选；ARM Windows/Linux 返回 `unsupportedReason`；macOS 架构 unknown 时 `ambiguous`。`detectPlatform(nav)` 基于 navigator（浏览器 UA/clientHints）；桌面端 macOS 区分 arm64/x64 在 WebView 里通常 unknown，需 Rust 提供（`std::env::consts::ARCH`）或让用户选择两个 dmg（landing 已有 ambiguous 分支）。
- `format.ts`/`useReleases.ts`/`DownloadCard.tsx` 为 landing UI。
- **landing 模块与产品共用同一 bundle**；landing 的 `localStorage` 缓存键 `cuepoint.landing.release`。landing 在桌面里直接 `fetch` GitHub 会被 CSP 拒（见 §2）。
- 发布产物：5 个安装包 + `SHA256SUMS` + `release-manifest.json`（`docs/desktop-distribution.md`）；Release 为 owner 创建的 **draft prerelease**，发布后才对外可见（`/releases` 列表仅公开发布才返回给未鉴权）。

### (a) 前端 fetch -> 内存 -> 交给 Rust 写盘
- 取数：必须用 `tauri-plugin-http`（`runtimeFetchFor`），原生 `fetch` 受 CSP 限制。现有 `runtimeFetch` 已有的约束：`authorizeRuntimeHttp(url, method, headers, body, scope)` 仅允许 `configured/result-download/search-probe/model-catalog` 四种 purpose；**github.com 与 api.github.com 目前无 purpose**，需新增类似 `model-catalog` 的固定 URL purpose（JS-only，Rust `validated_origin` 对 https 域通过；模型目录小节说明 “Rust is unchanged”）。GitHub release 下载会 302 到 `objects.githubusercontent.com`（或 release-assets.githubusercontent.com），`runtimeFetch` 每一跳重新走 `authorize` 且 `maxRedirections: 0` 手动跟随（最多 5 跳），因此新 purpose 需允许下载跳转域；每个新 origin 触发 `authorize_http_origin`（本地 128 上限，可复用）。
- 写盘：`saveNativeBlob(blob, filename)`（`src/lib/nativeSystemServices.ts`）经 `product_save_begin/chunk/finish`：**弹出系统“另存为”对话框**（`blocking_save_file`），256 KiB 分块，每块 `Array.from(bytes)` 作 JSON 数组传 IPC（体积约 4–8x 膨胀、很慢），SHA256 回执校验。体积风险：安装包大小未知（含 bundled SQLite、前端、macOS 14 版本约数十–上百 MB，Linux AppImage `bundleMediaFramework` 更大——未实测），内存全量缓冲 + 逐块 IPC 慢、无进度（需自行在循环里加进度）。`boundedResponse.readResponseBytes/readResponseBlob` 需要 limit 参数（现有响应上限 4 MiB 普通 JSON、8 MiB 目录；需新常量）。
- 优点：零 Rust 新依赖/命令；校验在 JS（`Sha256` 类 `src/lib/sha256.ts`，纯 JS 较慢）。缺点：大文件内存、慢、用户需选保存位置、“打开”仍要新命令。

### (b) Rust 侧流式下载 + 进度事件 + 校验
- 需新增 Tauri 命令（如 `desktop_update_download`）与事件（capability 已有 `core:event:allow-listen/unlisten`，可接 `emit`）。实现：用 `tauri-plugin-http` 的 reqwest（需在 Cargo 直接引入 `reqwest` 才能 `use`，或通过 `tauri_plugin_http::reqwest` 重导出——**已知 2.x 插件有 `pub use reqwest`，但vendored 版本未核实**），流式写入 `app_cache_dir()/updates/<name>.part`，边写边 `sha2::Sha256`，完毕与 GitHub `digest` 比对后 rename；URL 前缀校验 `https://github.com/ROYIANS/Cuepoint/releases/download/` 在 Rust 复刻（`releases.ts:isUnder` 的 URL 规范化逻辑需用 `tauri::Url` 重写）；`file_transfer.rs` 的 stage/原子发布/`paths.rs` 可复用其思想。
- 优点：不占 JS 内存，真进度，可取消，可固定目录（无对话框）。缺点：新增 Rust 代码量最大且无法本机编译；若直接加 reqwest 需改 Cargo.lock（`--locked`）；与 vendored http 插件的 reqwest 版本需一致；规范里 “Official requests bypass WebView CORS, not the application policy”，Rust 直连需自带策略；四平台均需验证；GitHub 的 `digest` 字段对旧 release 可能缺失（`sha256?` 可选，landing 已按可选处理），需有“无 digest 则回退到 SHA256SUMS 或拒绝”的决策。
- 校验源还有 release 内 `SHA256SUMS` 文件（`docs/desktop-installation.md` 提及），可作为 digest 缺失时的备选来源。

### (c) 仅打开浏览器下载
- 复用 `nativeOpenExternalUrl(asset.url)`（或 `<a href target=_blank>`，已被 `installNativeExternalLinks` 拦截），或打开 `release.htmlUrl`（`RELEASES_URL` / `INSTALL_GUIDE_URL` 在 `releases.ts` 已导出）。零 Rust 改动，唯一需要的网络是版本检查（JS）。浏览器下载自带系统隔离标记（Gatekeeper/MoTW 与浏览器路径一致）。

### 各平台“打开安装包” 与无签名提示（来自 `docs/desktop-installation.md`）
| 平台 | 资产 | 打开方式（系统层面） | 无签名提示 |
|---|---|---|---|
| macOS arm64 / x64 | `Cuepoint_<v>_macos_arm64.dmg` / `_macos_x64.dmg` | 双击挂载 DMG，拖入 Applications；`open <path>` 即挂载 | ad-hoc 签名、未公证：Gatekeeper “无法验证开发者/Apple 无法检查恶意软件”，需 系统设置 -> 隐私与安全性 -> “仍要打开”。若由本应用下载（无浏览器 quarantine 属性），可能不触发 quarantine（推断，未实测）|
| Windows x64 | `Cuepoint_<v>_windows_x64_setup.exe`（NSIS，currentUser 安装） | 直接 `open_path`/ShellExecute 运行 | SmartScreen “Windows 已保护你的电脑”，更多信息 -> 仍要运行；“未知发布者”；WebView2 缺失时安装器联网下载 bootstrapper。注意运行中的应用被覆盖安装需先退出 |

- 无 Windows ARM、Linux ARM、macOS universal 包。macOS 最低 14.0。
- 应用自动安装/重启均**不在范围**：`desktop-distribution.md`“Automatic updating is outside this package flow”，规范“No updater, signing credential … belongs in this lane”（`desktop-distribution.md:83`）。Tauri updater 需签名密钥，与现策略冲突（用户已提示）。

## 4. 版本信息

- `__APP_VERSION__`：`vite.config.ts:33` 与 `desktop/tauri/scripts/build-frontend-worker.mjs:20` 注入，声明在 `src/vite-env.d.ts:9`（`string | undefined`）。目前仅 `src/lib/diagnostics/errorReport.ts:56` 有私有 `appVersion()`（未导出，回退 `"dev"`）。桌面源 `desktop/tauri/package.json` version `0.1.2`；root `package.json`、Cargo、tauri.conf 三处与其必须一致（`desktop-distribution.md:~50` “must agree”，由 release 脚本校验）。web 构建的版本来自 vite.config.ts 读取的版本（根 package.json，具体字段未逐行核对）。
- Tauri `getVersion()`：`@tauri-apps/api` 在 `desktop/tauri/package.json` 为 2.12.2；根 `src/` 已在 `nativeSystemServices.ts` `import {invoke} from "@tauri-apps/api/core"`，故根也有该依赖。`app.getVersion` 需要 capability `core:app:allow-version`，现 `main.json` 未授予，调用会被拒。故以 `__APP_VERSION__` 为准最省事。
- 比较：`releases.ts` 的 `semverOf/compareSemverDesc` 未导出（内部函数）；只处理 `X.Y.Z` 三段（正则 `^desktop-v(\d+)\.(\d+)\.(\d+)$`），**不含预发布后缀**（`-rc.1` 的 tag 会被过滤）。GitHub `prerelease` 布尔字段仅作展示（`LatestDesktopRelease.prerelease`）。项目无 `semver` 依赖（`package.json` 未见）。版本检查“是否有更新”= 取最新 `desktop-vX.Y.Z` 与 `__APP_VERSION__` 数值逐段比较；`__APP_VERSION__ === undefined|"dev"` 时需处理。

## 5. 规范与门禁（硬性规则）

- `docs/desktop-distribution.md` / `.trellis/spec/frontend/desktop-distribution.md`：产品身份固定 Cuepoint/`dev.cuepoint.prototype.offline`/`cuepoint-prototype`；版本三处一致、tag `desktop-vX.Y.Z`；**无 updater/签名凭据**；mac ad-hoc、Windows 未签、Linux 无签；打包 workflow **仅打包，不跑测试/lint**（owner 决策 2026-10-12），GHCR workflow 才跑 tsc + vitest + models-dev:verify + build；Tag/Release 只有最终 publisher 可写；改动 tag 后源码需新版本（不移动 tag）。
- `native-product-runtime.md`：Tauri 主窗口信任检查；Rust 命令必须同步登记于 main capability、normal 与 acceptance 两份 handler 与 build ACL（`:269`）；HTTP 只能走 `authorize_http_origin` 动态授权 + JS 策略；“do not globally widen fetch/CSP”（`:328`）；原生 `tauri-plugin-http` 固定 2.8.2 且 vendored（`vendor/` 含 cancellation patch + provenance，改动需同步 hash `:191`）；Models.dev purpose 先例 `:196`，且注明“Packaged-window reachability and CSP for this origin have NOT been verified in a real Tauri window”——即 GitHub 的同类需求同样需真机验证；开桌面外链只走 `product_open_external`（`:257`）。
- 数据隔离：normal/isolated/IndexedDB 三个 lane 身份固定，存储初始化失败不得静默换 owner（`desktop-distribution.md` 末段）；下载目录建议用 `app_cache_dir`/用户选择，不得写入 `product-workspace-v1`。
- `desktop-ui.md`：Settings 为 rail 最后一项，**当前指向 `/settings`（redirect 到 About）**；页面使用 `PageHeader/PageContent`，单一主滚动所有者；ModuleLayout 左导航 260px、<768 变 overlay；Dialog 用 `createOverlayFocusReturn`；AlertDialog 必须含 `AlertDialogCancel`；禁止 `window.alert/confirm/prompt`；不新增第二个壳/页内独立 scroll wrapper。
- `quality-guidelines.md`：测试放 `tests/*.test.ts`，优先 lib/repo 层纯函数；不默认引入 RTL/组件快照；命令 `pnpm lint`（`tsc -b`）、`pnpm test`（vitest）、`pnpm quality`（`scripts/quality-check.mjs`）、`pnpm models-dev:verify`、`pnpm build`；本机使用 AGENTS.md 指定的 `/Users/xiaomengdao/.nvm/versions/node/v24.11.0/bin/pnpm`。desktop/tauri 自己有 `types/lint/quality(knip)` 与 `test:parity`（含 `generate-contract-fixture.mjs --check` + Rust `portable_contract` 测试）；knip 要求无未使用导出（`quality-guidelines.md` “Desktop Knip cross-package callers”）。
- 测试可行性：已有 `tests/runtimeFetch*.test.ts`（含 `runtimeFetchModelCatalog.test.ts`，可作为新 purpose 的测试模板）、`landingReleases.test.ts`、`landingPlatform.test.ts`、`runtimeExternalLinks.test.ts`、`runtimeSave*.test.ts`、`aboutPageSponsorSave.test.ts`——全部为注入 `fetchImpl/storage` 的纯 TS，无需 Rust。纯函数（版本比较、资产选择、digest 校验、设置搜索过滤/分组配置）均可在 vitest 覆盖；Rust 命令只能由 `cargo test`（需 Rust，本机不可）与 CI 四 host 构建验证（CI 不跑 Rust 测试）。可做的契约测试：build.rs 命令列表 / handler / capability / autogenerated toml 一致性文本断言（`desktop/tauri/scripts/*.test.mjs` 现有风格，`test:release` 用 `node --test`）。

## 风险清单
1. **CSP / 网络**：webview 内 `fetch(api.github.com)` 被 CSP 拒；必须走 `runtimeFetchFor` 新增 purpose（并校验重定向到 githubusercontent 的跳转）；规范要求禁止放宽 CSP；打包窗口可达性未验证（同模型目录先例）。
2. **GitHub API**：未鉴权 60 次/小时，`rate-limit` 回退（landing 已有 `FallbackReason`）；draft 不可见；`digest` 字段可能缺失；预发布 tag 不带后缀。
3. **Rust 无法编译**：任何新命令/依赖在本机无法验证；`--locked` 的 Cargo.lock 需 Rust 才能更新；build.rs/handler/capability/autogenerated 四处必须同步（漏一处运行期报 ACL 拒绝）。
4. **安装包大小/IPC**：方案 (a) 内存全量缓冲 + 每 256 KiB 一次 JSON 数组 IPC，慢且占内存；且会弹“另存为”框。
5. **打开安装包**：规范禁止 raw file opening，需新命令并限定到自身落盘路径；未签名触发 Gatekeeper/SmartScreen；Windows 覆盖安装需先退出应用；Linux AppImage 需可执行位。
6. **数据安全**：下载/安装前提示先导出项目 ZIP（`docs/desktop-installation.md` §5）；不要触碰 `product-workspace-v1`。
7. **架构识别**：WebView 无法可靠区分 macOS arm64/x64；需 Rust 返回 `ARCH` 或让用户选。
8. **偏好存储**：无现成 settings 存储，主题/语言仅有 `html.dark` 与 `zh-CN` 写死；“外观/通用”分区首版如含主题/语言切换需新增存储与 token 方案，规范未覆盖（desktop-ui 的 token 仅暗色）。
9. **路由**：`/settings` 现为重定向到 `/about`，AppFrame NAV 的 active 判断与顶栏 Logo 都链接 `/about`；新增设置路由要同步 `routeTree.gen.ts`、`AboutPage`、`aboutPageSponsorSave.test.ts` 及 desktop-ui 规范中 “Settings … currently redirects to About” 描述。

## 建议的最小方案轮廓（仅供主 agent 参考）
- 路由：`/settings` 去掉 redirect，成为带 ModuleLayout 左导航（搜索 + 分区：通用/外观/存储/关于与更新）的页面，右侧 `PageContent` 内分组卡片行（标题+说明+右侧控件，复用 `bg-card`、`border`、`Select/Button/Checkbox/Input`）；`/about` 可保留或并入“关于与更新”。
- 第一阶段（零 Rust 改动）：版本检查 = 复用 `fetchLatestDesktopRelease`（传 `runtimeFetchFor` 新 purpose，如 `"release-check"`，固定 `api.github.com/repos/ROYIANS/Cuepoint/releases` GET，仿 `model-catalog`）+ 新增版本比较纯函数 + `__APP_VERSION__`；“打开发布页”与“浏览器下载安装包”走 `nativeOpenExternalUrl`；“存储”分区展示数据信息暂仅文案或 Rust 后续命令。
- 第二阶段（需 Rust，需四平台 CI/真机验证）：`product_storage_info`（路径/大小/打开目录）与可选“应用内下载”（方案 b：Rust 流式 + 进度事件 + sha256 + URL 前缀校验，落在 `app_cache_dir`，下载完用新命令 reveal/open）。若坚持零 Rust，则方案 (a) 仅作小文件适用，不推荐大安装包。
- 测试：vitest 覆盖版本比较、资产选择（复用 `pickAssets`）、URL 前缀与 digest 校验、runtimeFetch 新 purpose（照 `runtimeFetchModelCatalog.test.ts`）、设置搜索过滤；可加 node 文本契约测试断言命令在 4 处登记；Rust 部分在无本机 Rust 时只能静态审阅并依赖 CI 构建。
