# 顺序整改关口

本清单不代替唯一进度源remediation-ledger.json；完成项必须带实际证据。

每单元依次：implement按所有关联finding机制修改 → 针对正常/异常触发回归与类型检查 → check独立看真实调用链/事务/测试 → main同步可执行spec与台账 → 下一单元。遇到未证实风险先验证，不把风险描述直接当修复要求。

每批结束：完整Vitest、类型检查、model snapshot verify、生产build、git diff --check；生成文件只有确认语义一致才恢复工具自己的格式变动。列出新增依赖、API兼容和未覆盖浏览器/真实供应商的限度。流程要求Phase3.4明确提出一次具体提交计划并等待用户确认；不自动push、发布或归档。
