# Independent SQLite host boundary

The libraries and Cuepoint already use the shared loop. The remaining behavior gap is a second actual consumer with durable independent state and a real process lifecycle. `examples/agent-todo/src` will own its SQLite schema, scope coordination, semantic persistence adapter, typed Todo tools, deterministic model and CLI. No Studio import, table or product schema is involved.

The coordinator holds a SQLite write lock in a separate sidecar connection for its entire lifetime; the business database uses short transactions. SQLite releases coordination after real process death. Every semantic commit verifies the live capability and current persisted owner/run/call predicates. Local Todo mutation, evidence and completed result share one transaction; serialization and abort checks precede COMMIT. Startup recovery only classifies saved state. Explicit resume invokes `executeRun` from built public core.

The same generic parser, approvals, loading, request segments, checkpoint writer, compaction and terminal predicates are consumed by this host. The deterministic model is the only replacement for HTTP. The Node24 conformance suite will own process handshakes/kill/reopen/second-live-owner tests, rollback/unknown/approval/checkpoint/segment/loading/summary tests. Root Node22 tests retain library responsibility and will not import the Node24 CLI.

`tooling/agent-example-check.mjs` will build and pack the actual libraries, verify packed dependency versions, install their tarballs into an outside-workspace empty offline store, compile copied example/types with emitted declarations and run the complete Node24 suite there. Docker workspace manifests, exact workspace/Knip/type/native discovery and a separate Node24 CI job are necessary consumers of these new files. Existing desktop packaging policy, dependencies and protected snapshots remain unchanged.
