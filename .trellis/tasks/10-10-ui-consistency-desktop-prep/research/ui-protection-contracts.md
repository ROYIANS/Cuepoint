# UI audit implementation guardrails — planning summary

Derived from [workspace and theme audit](./workspaces-and-theme-audit.md) and [routes and Studio audit](./routes-and-studio-audit.md); full source evidence remains there and must be read for the owner being changed. This compact injection summary avoids truncating the complete research documents. The user selected direction A (dark neutral sans desktop tools) and permits broad whole-app UI/navigation changes. The final implementation review remains pending; design.md is the current proposal.

- Current app is dark-only; white storyboard printing is intentional. Direction A retains neutral colors and shadcn control radius/border/focus defaults with consistent sans UI typography. No new library/font/desktop framework is presumed.
- Route inventory covers all 47 route files: 25 page adapters, 1 persistent Agent host, 3 view selectors, 10 provider/shell/outlet layouts and 8 redirects. This is not a count of unique visible screens. The coverage matrix has 31 contextual checks. Studio/project shells currently differ; the proposal shares their presentation while preserving route targets, action semantics, project guards and data lifecycles.
- Shared page/header/toolbar/state primitives are candidates, not existing universal owners. Use library/detail/editor/print width and density modes rather than a global max-width or blanket CSS override.
- Current titles vary in serif/sans, size17–36px and function name/promotional copy. The selected direction uses functional sans UI titles; candidate page/editor/body/meta roles are specified in design.md and do not flatten actual creative/print content.
- Asset editors are shared between Studio and project; preserve owner checks, keyed draft retention, commit failure/retry, upload cleanup and actual committed media.
- Studio library/search/filter controls and card actions retain their current semantics and ownership. Materials and IP retain captured revisions, dirty/pending close guards, version/adoption/archive rules and failed drafts. Shared control and overlay presentation must not remove these guards. Keep connector credentials out of audit artifacts and never click probe/save/disconnect merely for styling evidence.
- The Studio source audit identifies separate typography, width, toolbar, card/state and overlay systems. Replace decorative material left accent strips under the recorded user preference; keep aspect ratios and actual tab/filter ARIA semantics. Source risks such as nested scroll, hover actions and short-height dialogs require native verification before claiming failure or repair.
- Shot editing owns stable row anchors, deferred controls, DnD, deep-link/focus and inner canvas/table scrolling. Retain source geometry and input/overlay shortcut gates. Do not eagerly mount every offscreen row for style consistency.
- Audio editing owns timeline ruler/waveform/trims/clip coordinates, transport, player epochs and current history. Do not replace geometry units with generic layout tokens. Selection/arrangement previews retain exact snapshot/CAS/whole confirmation, original manually edited clips and focus return.
- Paid audio/music generation retains prepare/confirm separation, frozen model/input/connector/reference, bounded20/two-workers queue, explicit failed-only new approval and no paid replay on refresh/import. Styling audit must not call submit/retry providers.
- Music creator drafts/modes/details/player each have deliberate scope and scroll; preserve current version review, flush/re-read locks and real decoded duration.
- Agent uses scoped LobeHub/antd; avoid Studio-wide theme wrapping/global reset leaks. Preserve same mounted chat runtime across home/thread/tasks, route identity, manual disclosure, transcript scroll, reading/composer safe area, popup portal ownership, Stop and exact approvals.
- Project memory retains dirty/pending editors, owner-scoped CAS/version/review and failure feedback; list/detail styling must not erase unsaved content.
- Export/print remains episode-scoped and waits for actual loaded rows/media; preserve A4 landscape10mm margins, print chrome hiding and white paper. Native screen toolbar readability is a separate check.
- Native source coverage is not visual acceptance. Record individual inspected screen/state, desktop/narrow/short-height resize, keyboard focus/return and overlay reachability. Existing functional tests protect behavior; use actual screenshots/computed geometry for visual claims.
