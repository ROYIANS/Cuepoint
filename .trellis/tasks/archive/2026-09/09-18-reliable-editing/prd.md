# 编辑可靠性与测试基线

## Goal

保证本地编辑不会因快速导航、异步保存顺序或跨页面场次编辑而丢失，并建立可重复运行的数据层测试。

## Requirements

- **R1** 系列一句话、世界设定、集标题和故事使用统一的可 flush 保存机制。
- **R2** 保存失败必须可见并可重试；旧保存完成不能把新草稿标为已保存。
- **R3** 场次修改采用字段级仓储操作，故事页不能用过期整对象覆盖分镜页更新。
- **R4** 建立短时撤销基础，用于后续删除、排序和批量操作。
- **R5** 增加 Vitest + fake-indexeddb，覆盖 repo 与项目包关键不变量。

## Out of Scope

- 持久化完整历史、跨刷新撤销
- 场次和镜头排序 UI（由后续子任务实现）

## Acceptance Criteria

- [ ] AC1 输入后 400ms 内切页并刷新，最后值仍存在（R1）
- [ ] AC2 保存失败显示错误状态，重试成功后恢复“已保存”（R2）
- [ ] AC3 故事页与分镜页交替修改同一场次不会丢字段（R3）
- [ ] AC4 可注册一项短时撤销动作并执行一次恢复（R4）
- [ ] AC5 `pnpm test`、`pnpm lint`、`pnpm build` 通过（R5）
