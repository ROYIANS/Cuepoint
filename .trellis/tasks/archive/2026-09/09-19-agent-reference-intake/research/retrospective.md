# Reference intake retrospective

## Decisions preserved

- Project references are original evidence. Shared storage does not imply automatic injection into every conversation, acceptance as business facts, or promotion to long-term memory.
- Native image reading uses the same selected model and its normal tool continuation. A queued image is not an analysis result; actual pixel materialization happens just before HTTP.
- Source withdrawal is an availability change. Keep historical authored prose, but reject stale structured source bodies and image descriptors across retry, history tools and summary preparation.

## Lessons from verification

- A new media owner must join both GC and approval-time usage/CAS projections. Otherwise a valid source appears orphaned until commit.
- Character limits, coverage and ZIP checks must count exactly the same persisted text, including inserted separators. A 100,000-line fixture caught the divergent definitions.
- IndexedDB fake implementations do not replace native transaction tests. The source-evidence path uses bulk reads and passed 180 repeated descriptors in Edge.
- Async UI selection must include project/thread/model/source keys. Home-to-thread migration must move attachments before navigation and clear only after successful run creation.
- PDF.js needs local CMaps/fonts for Chinese PDFs. Browser worker packaging differs from upstream Node loaders. Mammoth is static inside a lazy worker graph because the default Vite IIFE worker cannot emit dynamic chunks.
- Prepared request audit cannot claim network transmission. Compression may preserve an image source descriptor without preserving pixels; the UI must say so.

## Follow-up boundary

Batch generation remains a separate child of the workflow/memory task. No automatic scheduling, hidden model switch, legacy dataset migration or broader editor redesign was added.
