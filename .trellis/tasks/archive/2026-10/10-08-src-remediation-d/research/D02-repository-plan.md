## Atomic contracts that determine the split

1. **Project and thread cascades.** `deleteProject:326` retains the existing one rw transaction: audio rows, IP link, material bindings, project-scoped material archival/events, references/chunks, memories/versions, proposals/jobs/batches/items, video entities/media and parent deletion. Keep immutable library snapshots and IP profiles, and preserve current project deletion semantics rather than replacing owned media deletion with orphan collection. `deleteChatThread:1941` first captures generation input/result/before media candidates, deletes batch/job/context/task record and wrapup history/run/call/chat rows, then performs global orphan checks inside the same outer transaction. Surviving production/reference/material/audio uses still protect results. A cleanup failure must roll the whole thread cascade back.
2. **Creation and copy/release commands.** `createProject:224` writes project+first episode and conditional IP link atomically; `createAudioMusicProject:2024` writes project plus initial audio chapter/voice track or music draft, with its current IP checks and store set. Do not replace these with sequential owner API calls. C03 `add*:880/974/1045/1103` and `putMedia:726` retain their narrow parent+child transactions, nonstudio owner read, create and touch; studio needs no project row and nested wider Agent writes remain compatible. Studio copy retains its whole asset/media/project transaction, source validation, duplicate provenance refusal, distinct media IDs and touch. Material release retains production+events scope, binding checks, retained flag changes, cleanup and final event as one command; failure restores all of them.
3. **Media survival.** `collectMediaIds:648` keeps its optional project scope for package use and global scope for cleanup. It includes covers, all asset/shot slot refs/results, usable references, material uses, `libraryRetained`, audio takes/works/exports, audio generation input/results and speaker reference media. `deleteMediaIfOrphan:736` additionally protects proposal before/change results, single-job inputs/results, item draft inputs and batch application before/results. Do not merge these APIs into a new collector that accidentally changes package contents or historical retention. Nested cleanup joins the caller's compatible production transaction; do not perform it after commit.
4. **C05 validation and A04 CAS.** Generic asset patches reject an own `slots`, and shot patches reject own firstFrame/lastFrame/clip even when undefined, before picking fields. Dedicated slot and cover writers retain owner, nonempty Blob, declared kind/MIME checks inside their rw transaction. Asset/still results are images; clip permits existing image planning placeholders and videos. Keep ordered refs, optional empty normalization, same-final convergence, current-field baseline comparison, and write+project touch+old-media recycling rollback. Public signatures, including optional baselines, are preserved. Extraction does not broaden `updateProject` or any patch API.
5. **Ordered narrative and undo.** Episode last-survivor checks, exact membership reorder, script-range normalization, beat+shot group reordering/duplication and restore assignment guards stay in their current transaction. Shot creation validates project/episode/beat/assets and seeds beat choices only at creation. B03 membership intent reads current cast and validates all survivors. A02 bulk inverse captures actual normalized touched-field before/after and validates every target before restoring only those fields. A03 `deleteEpisodeShots:1786` reads current shots and all slot media/Blobs, calls nested `deleteShots:1755`, and returns only after success. Keep its stricter scoped validation separate from the tolerant generic `deleteShots`. `restoreShots` retains its current existing-ID, relationship/order and rollback behavior; no UI pre-read replacement or new validation policy is proposed.
6. **Import/export remain complete commands.** `projectPackage.ts:756–825` obtains JSON, referenced media and Blob metadata inside one readonly snapshot using `collectMediaIds(projectId)`. Move that import only. Modern original identities are checked before repair/remapping (`:400–448`, call `:935`), with normalized collision checks retained in the existing parser; legacy absent/empty episodes keep synthesis, equal beat IDs in different episodes remain scoped, and unknown `extra`/MIME/default relationships remain compatible. The complete insert transaction at `:1117–1150`, audio remapping and rollback stay in the existing package module; do not route import rows through separate create APIs. Connectors, chat and IP association remain excluded from ZIP transfer as before.
7. **Connection and chat identity.** Connector upsert lookup/write plus explicit alias rotation and disconnect remain atomic; historical IDs/fingerprints do not change and selectors remain active-only. Chat default-policy preparation stays before its current creation write. Binding keeps expectedProjectId and no-existing-run/message/task guards in one transaction. Do not create another generic message patch path for run-owned output; existing `updateChatMessage:1994` ignores missing/run-owned rows.
