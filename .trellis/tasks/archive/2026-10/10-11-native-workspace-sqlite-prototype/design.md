## Data authority and exact portable contract

Minimal versioned metadata DB stores workspace UUID, prototype projects, assets, project references/timing and durable import intents. Ready asset: stable ID, owner, exact WorkspaceRef, display name, MIME, positive bytes and SHA-256. `kind: media | output` shares canonical byte paths rather than introducing a second codec. Foreign keys/owner closure are checked. These are named prototype tables, not production JSON dumps or 49-table migration.

Create exclusively reserves a fresh root; open checks existing schema/identity/integrity/closure and cannot initialize over invalid/incomplete state. Device-local roots, source selections, writer DB/profile/credentials are excluded from portable backup. Availability verification reports missing/corrupt independently of metadata, without removing logical references/timing. App-owned generated JSON does not ingest external edits.

Wire oracle anchors: `src/lib/workspace.ts:37` workspace identity, `:46` well-formed exact ID, `:59` lowercase UTF-8 hex, `:70` owned safe ref, `:86` mediaWorkspaceRef, `:93` lexical resolve; `src/lib/sha256.ts:7/:90` digest. TS frontend/generator import actual helpers. Rust rederives exact refs from IDs and rejects noncanonical payloads; it never normalizes IDs. Generate immutable golden corpus through TS, recording generator/source hashes: studio/project owner, case pairs, composed/decomposed Unicode, emoji, literal separators/reserved-looking IDs, wrong owner, traversal, malformed wire and hash chunk/block/padding boundaries. Serde/wire tests must reject lone-surrogate strings/extra fields before replacement can alias JS IDs. Native length bounds add OS safety without changing accepted TS encoding. No Node sidecar merely for helper reuse.

## Containment, operation queue and writer

Canonicalize legitimate OS parent aliases (such as macOS /var) and duplicate root identities. Reject symlink as app-owned root or managed component; check DB/journal/stage/final/backup ordinary type/link state before access/publication/cleanup. Access managed bytes only by authoritative derived ref. Reject excessive encoded component/path length instead of renaming IDs. Source selections never become cleanup targets.

Separate device-local writer.sqlite connection holds BEGIN EXCLUSIVE for opened-workspace lifetime with a small bounded busy timeout. Metadata uses another dedicated connection and short transactions; no pool may swap the held connection. Genuine process death releases SQLite OS lock, requiring no PID/stale-lock deletion. Queue import, writes, backup, recovery and close. Freeze payload/workspace generation/operation identity before waits; recheck on dequeue and immediately before irreversible work. Cancellation targets only the caller's own live operation.

Protection covers cooperating app processes and tested static/link/lifecycle attacks on local filesystems. Rust does not itself prevent hostile concurrent ancestor replacement. Record which accesses actually use descriptor-relative/no-follow operations; any remaining check/open race is explicit. Network filesystem locks and physical power loss remain unproved.

## Import commit and idempotent recovery

1. Trusted Rust dialog selects source. Snapshot project/options/generation before async selection/queueing; canceled dialog creates no intent. Validate handle/type/size and derive new asset ID/ref.
2. Commit intent identifying only validated app-owned stage/final paths before writes. Create unique same-filesystem stage exclusively. Copy/hash at most 256 KiB chunks with real cancellation/lifecycle checks; reject empty/truncated/error or detected changing source. Flush complete bytes and persist verified size/hash to intent. No copy/hash inside metadata transaction.
3. Recheck owner/lifecycle/cancel/containment and target absence. Publish same-filesystem hard link then unlink stage, or proven atomic exclusive equivalent. No overwriting rename fallback. Flush parent directory where supported; retain actual unsupported fsync evidence.
4. One short transaction inserts ready asset/optional reference and deletes intent. Final owner/operation checks occur immediately before COMMIT. Once SQLite reports commit success, committed result wins a later abort.
5. Reopen reconciles only validated recorded intents. Clean unfinished owned stages/uncommitted finals; never scan-delete unknown/source files. A crash between link and unlink leaves a legitimate two-link **same intent-owned inode pair**: verify that pair, while rejecting external aliases. Committed rows without intent survive. Ambiguous intent ownership yields focused error instead of destructive guessing; repeated recovery is idempotent.

Compile-gated test CLI pauses after intent, partial copy, publication, pre-COMMIT and post-COMMIT. Coordinator kills actual child process, reopens and asserts authority. Test hooks are absent from normal command/release builds. Additional tests cover I/O/fsync errors, source change, queue-input mutation and cancellation/close races; distinguish injected failures from actual filesystem proof.

## Consistent backup and restore

Backup owns queue and exclusively reserves new destination, rejecting even existing empty directory. `rusqlite::backup::Backup::step` runs bounded pages with cancel/elapsed-time/Busy/Locked limits, not unbounded convenience retries; handles stay in storage worker. Validate standalone snapshot DB schema/integrity/identity, derive required closure from snapshot, bounded-copy each ordinary file and compare size/hash. Queue excludes app mutations; external changes cause verification failure.

After DB hash and complete ref/file closure pass, flush/publish a strict completion manifest last. Closed format/schema/workspace/DB-hash-size/asset-closure fields reject unknowns, duplicates and ambiguity. Directory existence is not completion. Missing/corrupt required bytes fail backup. Exclude device-local writer/profile/credentials.

Restore verifies strict manifest, DB identity/integrity/closure and files, exclusively reserves new root, copies/rechecks bytes and marks completion last. Open rejects interrupted restore and cannot initialize it. Preserve exact UUID/refs/records/hashes; existing destination bytes remain untouched. Report incomplete failed destination and never silently reuse it. Actual process-kill tests before/after completion and corruption/traversal/duplicate/wrong-ID cases are permanent. Local backup does not publish remote checkpoint/provider acknowledgement.

## Tauri commands, ACL and native file boundaries

Named commands cover native-dialog create/open, state, fixture project save, selected import, cancel-own-operation, availability, dialog backup/restore, close/reopen and bounded managed reads. Serde deny_unknown_fields, finite enums/IDs/sizes and focused errors define wire DTOs; frontend parses unknown results strictly. Rust resolves paths, not renderer payloads. Read bytes by asset ID plus bounded offset/length (maximum 256 KiB) with owner/containment/hash verification. Small fixture media up to 32 MiB assembles Blob/object URL. One protected read operation or final checksum must prevent mixed bytes if file changes between chunks; revoke object URLs on dispose. This transport does not claim large-video random access.

Explicit custom-command ACL generation is required: build.rs uses tauri_build Attributes/AppManifest::commands and allow permissions bound to known main window; invoke_handler defaults do not provide that restriction. Explicitly select capability IDs in config. Deny remote capabilities/window creation and unneeded generic plugin/core defaults. Native handlers also validate trusted window/packaged origin, current workspace generation and operation ownership. Dialog results remain native-owned. No renderer SQL/fs/shell/HTTP powers and no wildcard asset protocol scope.

Bundled app protocol serves local Vite assets. CSP permits bundled script/style/font and only needed Blob/worker/media/IPC sources; no eval, iframe, remote navigation or popup. Verify exact origin/MIME/worker fetch in packaged app. Normal build is offline. Acceptance build has distinct identifier/profile/native feature/frontend flag and only one ephemeral-token loopback SSE endpoint/CSP exception. The test launcher reserves the one loopback port before building its exact-origin acceptance CSP, checks the real packaged Origin, and supplies an ephemeral test-only Bearer token to the existing adapters. Close that server after the fixture. Confirm those commands, hooks, reporting and network policy are excluded from normal release.

## Evidence, measurements and rollback

Native CLI covers storage/process death; compile-gated in-window harness calls real normal commands/helpers under packaged origin, plus CUA/manual observation of OS dialogs/playback/print. Fixed bounded acceptance reporting goes only to a preselected native evidence destination and is absent from normal build; it does not bypass command ACL. Current official macOS WDIO embedded plugin exists, though direct tauri-driver lacks native macOS driver; prefer this small internal harness without adding a full WebDriver stack. Label CLI, in-window assertions, UI screenshots and human confirmations separately.

Build normal `.app` and distinct acceptance bundle. Measure bundle/archive bytes, startup-to-ready cold/warm method and repeated readings, idle/media native/renderer/helper process-tree RSS with actual workload and OS/WebView/build versions. RSS sums may double count shared pages; record method/limits. No unaccepted Electron comparison or production-size extrapolation.

Run separate strict native/frontend gates plus unchanged relevant root gates. Freeze source manifest for independent full A+B review; keep raw failures and revalidate fixes against final hashes. Critical capability failure cannot be waived silently. Stop only prototype processes. Cleanup targets confirmed task-owned generated roots/toolchain paths, never global Rust/user data. Before final commit archive only manifest-owned obsolete Electron source preserving paths/hashes; unknown files and earlier probes remain. Parent retains other OSes, large-media transport, production records/history/secrets, live sync and final runtime decision. Framework-native plugins do not implement the future user plugin marketplace.
