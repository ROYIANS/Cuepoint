## Review findings and final corrections

| Initial finding | Current correction and reviewed proof |
| --- | --- |
| Structural ownership accepted caller-created fake capabilities. | Private unique-symbol branding and WeakMap identity/lifetime state reject forged capabilities. Studio tests refuse execution/resume before context writes or HTTP. Checks do not trust a supplied method. |
| A real wrong-thread capability could reach resume/context writes. | Execute/resume validate identity, held lifetime and thread before acquiring the execution claim or mutating a resumable run. Wrong-thread tests retain the interrupted row and make zero requests. |
| One capability could enter concurrent executions. | Private synchronous admission rejects concurrent reuse. Production send/retry/resume paths pass the actual held token. Tests verify one lock acquisition, one request and successful legitimate completion. Direct execution acquires exclusion without recovering its newly created run. |
| A callback could return while its detached execution remained active. | Closing the callback stops new execution admission and drains the registered promise while ownership remains held, then expires it before lock release. An actual deferred write tool proves a competitor is refused, the business write completes once, the old token expires and a new owner can enter. A second test preserves the callback's sentinel exception when the execution also fails during drain. No remote-cancellation or timeout-based death claim is made. |
| Atomic success could be invented by an unrelated completion write. | Core requires durable completed confirmation, retains committed results after a later throw and preserves unknown certainty after absent/failed confirmation. Direct core tests cover these cases and forbid the independent completion transition. Existing Studio atomic business/evidence/result commitment stays in its original transaction. |
| Expected call authority was checked outside the actual running-claim transaction. | The existing transition transaction now checks the expected execution/call/step/arguments/metadata/decision/preview/override projection and revalidates current offer/parser/metadata/permission/scope before pending/approved becomes running. Last-moment argument, offer and decision negatives exercise the real transaction and assert zero execution. The first offered/status-only tests did not isolate this last window and were strengthened before acceptance. This predicate is confined to claiming; it does not reject unrelated legitimate job/recovery updates. |
| False completion or ignored checkpoint writes could produce confirmed events. | Nonatomic completion reconciles a false write before success; otherwise it fails closed. The existing checkpoint transaction returns applied boolean; core only emits confirmed checkpoint for true. Stale/terminal storage behavior still preserves saved output. Round save and approval park were separately traced and throw on stopped runs instead of silently ignoring writes. Budget pause reports the actual saved status without introducing another writer. |
| Generic argument dispatch remained in Studio despite the approved inventory. | `validateToolInput` is a public core mechanism; Studio supplies only safe diagnostic constructors. Direct tests cover duplicate/unoffered/missing tools, exact size boundary, oversize refusal before schema parsing, malformed JSON and original schema error/input propagation. |

Events now carry `runId`, a host-supplied invocation `executionId` and invocation-local increasing sequence. The public contract explicitly disclaims a durable cross-restart counter. Output is provisional; notifications follow confirmed accepted operations. Observer failure cannot undo persistence, and credentials/opaque provider continuation are absent from event payloads.

Actual Studio credential tests supersede the initial helper-only auxiliary limitation: a real summary request sees a persisted running compaction and uses the current saved old key despite an obsolete entry key; rotating the row while returning that summary makes the following actual main HTTP use the new key. The compaction and run complete. A separate actual auxiliary path rejects changed frozen connector identity with zero HTTP and failed compaction/run state. Resolver-only deletion/redaction checks remain supplementary evidence.
