# Agent 体验精简与稳定性

状态：规划中。用户已确认范围、行为规格和视觉方向；最终计划待用户批准后才能 `task.py start`。

## Goal

让创作助手的对话界面"简约不简单"：成功时安静，只在需要用户行动时出声，同一件事只出现一次；同时修复审计确认的缺陷并降低复杂度，使后续能力升级（重试、并行、保活等）有稳固基础。参照 Claude Code / ChatGPT 的交互：助手回复无气泡，工具调用为紧凑的时间线。

## Background

- 用户反馈此前 ChatGPT 生成的 Agent 代码仍有缺陷，界面冗余，不符合"简约不简单"（例："成果声明未检查"、"工具调用存在失败或拒绝 / 回复已结束；成功调用的记录仍保留，未完成的调用不能计为已完成工作。1 项调用失败。"）。
- 2026-10-13 范围追加（用户，实施中途）：参照 Cursor 的对话侧栏重做话题侧栏，并继续优化工具调用样式（去掉下划线与悬停背景）；侧栏话题默认按项目分组，可切换为按时间合并展示。这修订了原先"话题侧边栏不改"的范围边界。
- 本轮决策（2026-10-13）：范围选"精简 + 稳定"，不新增桌面端能力；"结束前检查"收窄触发条件；"成果声明"链整体删除；对话区做极简重做（助手无头像/标题/气泡，用户保留气泡无头像）；工具调用改为时间线；批准按钮放在工具调用行。
- 此前 2026-10-10 的规范 `agent-execution.md` "Bounded terminal finishing check" 明确写了"用户批准该额外请求与只读成果审查""不得为保持旧计数而关闭该功能"。本任务经用户重新决策收窄/删除它们，是对该决定的有意修订，需同步修订规范。
- 证据来源：`research/ui-redundancy-audit.md`、`research/runtime-capability-gap.md`、`research/code-defect-audit.md`。其中缺陷为读代码推断、未运行复现；对标 Claude Code/ChatGPT 为知识推断。

## Requirements

### R1 — 成果声明链整体删除

删除 `finalReview.ts`、`runFinalReview.ts`、`db/agentFinalReview.ts`、`domain/agentFinalReview.ts`、`AgentFinalReviewStatus.tsx`、`run.finalReview` 字段及 `final_review` 指标用途，以及 `finalReviewEvidence.ts` 中仅服务它的部分；移除 `runChat.ts:318` 的额外请求。必须保留有其他消费者的：`inspectAudioGenerationOutputs`（`audioGeneration/runtime.ts:385`、`db/taskAudioGenerationEvidence.ts`、`db/audioGenerationBatches.ts:61`）、`inspectTaskGenerationOutput`（`wrapupEvidence.ts:176`、`db/agentTaskRecords.ts:146`）、`ownedAgentAudioBatchJob`、`describeRunWrites`（还被 `finishingCheck.ts` 使用）。已存储的旧 run 中 `finalReview` 字段须不致读取失败（兼容或忽略）。

### R2 — "结束前检查"收窄

仅在以下情况触发：计划仍有未完成步骤，或本轮实际调用过工具。纯问答（无工具调用、无未完成计划）直接结束，不多发请求，首次回复不被降级进过程记录。对话模式、停止、审批边界、步数预算仍优先。同步修订 `agent-execution.md` 的相关契约与测试要求。

### R3 — "成功时安静"的消息界面

一轮完成后默认只显示：回复正文；淡色操作栏（复制；失败或可重试时的「重新生成」；模型名、速度、token 仅悬停显示）；若本轮改动过数据，一行「已保存：…」（点开为记录链接，保留现有 `AgentWriteOutcomes` 的条目与跳转，删去三段免责说明和"缺少可核验记录"）；折叠成一行的过程记录「用了 N 个工具」。

- 删除：成果声明所有行、"执行记录"弹窗（`describeRunExecution` 的诊断面板）、头部 `execution.label` 的成功/中性类标签与全部免责 `detail`、"含 N 项失败"、计时器实时跳动（保留运行中的进行状态）、写给模型看的"参数校验失败，操作未执行……"提示（`ValidationFailureNotice`）、重复的计划展示（只保留一处）、消息正文与底部重复的"（已停止）/已保留收到的内容"。
- 状态只在需要用户时出现：待批准、结果待核实、已暂停、已中断，每个事件只在一处出现（见 R4）；整轮失败仅在消息底部一行红色错误 +「重新生成」；用户停止仅一行「已停止」。
- 运行中的"正在执行/正在思考"提示只保留输入框上方一处。
- `describeRunExecution` 若删除面板后无消费者，则一并删除；`selectActivityAttention` 因可行动而保留。

### R4 — 工具调用时间线与批准

- 过程记录按时间顺序：说明文字、思考（折叠）、每个调用一行"图标 + 动作 + 对象"（如"读取了镜头 3"），成功调用仅图标、无"已完成"文字；连续同类调用合并为"读取了 N 项资料"，点开见逐条。
- 运行中展开并实时刷新，结束后自动收为「用了 N 个工具」（保留现有行为）。
- 失败的调用在时间线直接显示一行红色错误原因，无需展开；`RecoveryFailureNotice` 中只保留"结果待核实"，其余折为一行错误。
- 参数与返回结果、效果类别（读取/编辑/联网）、高风险标识下沉到最内层，默认不出现，仅高风险且待批准时显示在批准行。
- 批准：待批准的调用行自动展开，直接显示要做什么及关键参数，旁边是「批准」「拒绝」。输入框上方「需要你处理」卡片只保留简短指路（如"1 项待批准 · 查看"），点击滚动并聚焦到该行；卡片中不再放第二套批准按钮。付费生成、生成审核、音乐审核等现有确认流程语义不变。
- 同一事件只在一处完整出现：头部 label、detail、composer 状态条、卡片、消息底部、调用行、group badge 之间的重复一律合并。

### R5 — 对话区视觉

- 助手消息：无气泡、无头像、无标题、无时间行，仅正文；时间、模型信息悬停显示。用户消息：保留右侧气泡，去掉头像。
- 移除 `ChatItem` 文档样式对助手消息的依赖（若可简单实现则自绘，否则以样式覆盖但不再增加 `!important`）。
- 输入框保持现有结构、位置与行为，仅清理样式；欢迎页、话题侧边栏、头部不改（头部/侧栏已在上一轮完成）。
- 清理 `agentChat.css` 中为覆盖库默认样式而增加的 `!important`，不得改变输入框展开、滚动归属、回到底部、回合导航等现有行为。

### R9 — 工具调用样式收敛（追加）

过程记录的调用行改为纯文字行：动词为前景色、对象为浅灰；无下划线（含"查看…↗"链接，如 `agentChat.css` 的 `.agent-change-link`）、无任何悬停背景（含过程摘要行使用的通用 ghost 按钮背景）；悬停只让文字变深，展开箭头仅在悬停或键盘聚焦时出现。尽量从调用标题与 `preview` 中取出对象（如"读取镜头 3"），取不到时退化为标题。键盘聚焦环保留（可访问性），但不得形成常驻的背景或下划线。

用户看过实际效果后的追加要求（2026-10-13，R9b）：
- 层级清晰：过程区整体缩进在摘要行之下；每个调用展开的内容缩进在所属那一行之下，并以细竖线与该行相连；摘要行下方不再有横分隔线；展开内容不得看上去与外层行并列。
- "参数与返回结果"改为带箭头的安静折叠行，置于该调用展开内容的最后，缩进对齐。
- 批量创建的实体链接不再逐个铺开：预览里的主链接是唯一默认可见的链接；逐个实体链接收进一个「N 项明细」折叠行，默认折叠。
- 对象与标题相同（或标题已包含对象）时不重复显示（避免"创建镜头 · 创建镜头"）。
- 参数无效类失败（模型会自行纠正的校验失败）用弱化的灰色单行显示，不用红色；红色只保留给真正的执行失败。
- 执行计划只在进行中/待办的条目旁写状态文字，已完成仅用图标。

### R10 — 话题侧栏参照 Cursor 重做（追加）

- 结构：品牌行（logo + 小光点，已有）→ 「新话题」置于首位并为主入口样式、「搜索」、「任务」→ 话题列表。去掉"话题 N"小节标题。侧栏不含设置入口（已在全局导航）。
- 列表：默认按项目分组，每个项目为可折叠小节；无所属项目的话题归入「未关联项目」；所属项目已被删除的话题也归入「未关联项目」（不显示为可用项目）。用户可切换为"按时间合并展示"（沿用现有今天/昨天/月份分组与排序规则，不再按项目拆分）。分组方式保存为本机界面偏好（`localStorage` 键 `cuepoint.agent.topicGrouping`，与 `cuepoint.agent.sendShortcut` 同一先例），默认按项目；读取到无效值时回退默认。
- 行：左侧标题（单行截断）、右侧相对时间（如 3 小时、28 天）；悬停或键盘聚焦时，相对时间被重命名/删除操作替换；当前话题以柔和背景标示；悬停提示显示完整标题与所属项目。不新增置顶、归档等无数据模型支撑的功能。
- 搜索：保留现有按标题搜索，搜索结果在当前分组方式下显示，匹配项所在的折叠小节自动展开。
- 保持：窄屏时侧栏的覆盖层行为、折叠时头部新话题按钮、`useThreadDeparture` 的离开确认与 `openThread/onNewTopic/onRename/onDelete/onOpenTasks` 回调不变。

## Technical Notes and Risks

- 删除成果声明链涉及 `domain/agent.ts`（run 字段）、DB 层、指标 purpose 和多处测试；`finalReviewEvidence.ts` 含共享函数，必须先查清消费者再拆。
- "结束前检查"变更会改变付费请求计数，测试与规范中"必须断言真实付费请求数"的要求需同步更新。
- D2 的交互（确认 vs 保留进度）影响恢复语义，与 `agent-execution.md`、`runOwnership` 的锁和中断恢复契约相关，设计阶段要明确。
- 批准按钮位置变化须不破坏 `useAgentActivityNavigation` 的滚动/聚焦、生成审核与音乐审核对话框的草稿所有权（`AgentRunDetails.tsx` 注释"Keep mounted: review dialogs own unsaved drafts"）。
- 聊天界面当前无测试，视觉与交互回归风险高，必须靠新增测试加真实窗口检查。
