# 爱分镜核心管理

## Goal

给个人用的纯前端分镜工作室：在浏览器里管理项目、角色/场景资产和分镜表。不接 AI。导入导出项目包是备份通道，也是以后 Codex skill / BYOK 写入同一份数据的契约。

## User value

作者可以在本机浏览器里建项目、维护角色和场景参考、按表格编辑分镜（画面/参考图/可配置列），并把整个项目导出给外部工具或另一台机器再导入。

## Confirmed facts

- 仓库几乎为空：占位 `package.json` / `index.js`，无业务代码。
- 无后端、无账号；数据留在当前浏览器 IndexedDB。
- 部署形态是静态 SPA，每人用自己的浏览器存储。
- 截图是分镜制作页的视觉标准；顶栏「故事板 / 拍摄计划 / 拍摄报告」只是分步示意，本任务不做真实功能。
- 不接文生图、图生图、自动分镜、BYOK。
- 父任务只做需求总账和跨子任务验收，不作为实现入口。

## Child task map

1. `09-17-app-foundation` — 脚手架、项目 CRUD、IndexedDB、导入导出、工作区壳、顶部分步占位。
2. `09-17-asset-library` — 角色 / 场景资产库（依赖 1）。
3. `09-17-shot-editor` — 按截图落地分镜表并挂资产（依赖 1、2）。

## Requirements

- **R1** 用户可以创建、重命名、删除项目，并在项目列表看到它们。
- **R2** 用户可以把一个项目导出为 `aifenjing-project-v1` zip，并在本机或其他浏览器导入还原（含图片）。
- **R3** 进入项目后有工作区壳：返回列表、项目名、分步顶栏；默认进入分镜制作；资产库有独立入口，不塞进分步 Tab。
- **R4** 故事板 / 拍摄计划 / 拍摄报告为占位页，不创建第二套镜头模型。
- **R5** 用户可以为项目维护角色资产：名称、简介、外观说明、备注；每个形象槽（正面/侧面/背面/表情/服装）的主体是提示词、参考图、参考视频，外面只显示最终生成素材。
- **R6** 用户可以为项目维护场景资产：名称、地点、时段、氛围、备注；每个槽（全景/中景/细节）同样以提示词+参考为主体，结果图/视频只作预览。
- **R7** 分镜表按用户截图交互：固定列（顺序、镜号、画面、参考）+ 可开关列。画面/参考都是生成槽：点击进入提示词与参考，空态分别为 `+` / 虚线框；行间插入；底栏镜头总数与总时长。
- **R8** 镜头可关联角色和场景，但不在单元格内编辑资产详情。
- **R9** 列显隐保存在当前项目。导入时不认识的 JSON 字段必须保留。
- **R10** 产品内不出现任何真实或伪装的 AI 生成调用。

## Out of scope

- 文生图 / 图生图 / 剧本自动分镜 / BYOK
- 后端、登录、协作、云同步
- 拍摄计划、拍摄报告的真实功能
- 把故事板做成第二套镜头实体
- 复杂批量填表

## IA revision (2026-09-17)

项目内步骤改为 **故事 / 世界 / 分镜 / 制作**。工作室外导航补 **道具**（与角色、场景、风格并列；道具库先占位）。

已确认的嵌套：

- **项目 = 一部戏 / 一个系列**。短片默认只有隐形的一集，不强迫分季分集。
- **季** 不是一等对象；需要时只是集上的编号。
- **世界** = 一直为真。含 **设定**（世界观 / 背景 / 规则，三块可写文本，不是生成槽）+ **名册**（角色 / 场景 / 道具 / 风格）。
- **故事** = 发生了什么：整部戏的一句话（可选总大纲）+ 每一集的剧本和场次。宇宙背景不放故事里。
- **分镜 / 制作** 跟当前集走。镜头最终要挂在集上，不能整部戏共用一张表。
- **场** = 一组镜头的可选打包，不是另一种镜头，也不是世界里的场景资产。世界的「场景」是地点；场是这一段戏。
- 故事页的「场次」和分镜表里的「场」是同一实体：故事加一场 = 分镜一个空场。
- **镜头可以没有场**，单独躺在表里。短片可以全程不建场。
