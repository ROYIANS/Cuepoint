# Studio source ownership and final contracts

Baseline: child-1 source checkpoint `bb3a9580`, accepted verification archived under `../../archive/2026-10/10-15-monorepo-app-boundaries/verification.md`. The executable ledger assigns every current Studio file once. `domain/types.ts`, production constructors and shared guards require symbol-level ownership splits; bodies remain unchanged. No retained old-source runtime bridge is planned.

## Layers and public contracts

- **app** composes bootstrap/router/frame, ZIP/import/export/checkpoint workflows and explicit integration seams. Aggregate deletion belongs to its command owner: `projects/commands/lifecycle.ts` defines `deleteProject` and `setProjectArchived`; `agent/commands/lifecycle.ts` defines `deleteChatThread`; video episode deletion remains video-owned. Each original complete transaction body is preserved. Feature UI may call named app workflows; feature commands/models and platform mechanisms may not depend on app composition. App draft UI is an explicit presentation integration, separate from the neutral primitives.
- **features** owns named models/commands/queries/UI and product Agent adapters. Commands accept the existing optional final `ProductStore`; a `StoreTx` must propagate unchanged to all nested readers/writers, receipts and results. Cross-feature consumers use documented concrete command/query/service/adapter entry modules; internal helpers and arbitrary UI deep imports are forbidden. Models have one owner; genuine shared relationships use type-only edges. No omnibus barrel replaces domain/db/lib.
- **platform/storage** owns storage contracts, adapters and singular schema/table registration, has no React/app or product-integration runtime import. Central registration may type-import feature row models. Historical browser schema normalization is a named adapter concern and calls authoritative feature pure parsers, never commands/UI.
- **platform/product** is explicitly the product integration layer, not storage machinery. `store.ts` preserves one import-time fixed owner selected by the trusted runtime profile; app awaits its initializer before rendering. `queries.ts` binds React observation to that exact typed owner; `drafts.ts` retains the existing process-local draft barrier. No global configure/service locator, second database or new transaction policy is introduced.
- **ui** owns neutral primitives/theme/formatting/focus helpers, with no durable business reads/writes.

## Final symbol owners and test placement

`domain/types.ts` is removed. Identity is `platform/identity.ts`; package format is `platform/data/packageFormat.ts`. Library owns ownership/assets/media/slot models; Video owns shots/story/episodes/world/format; Projects owns Project and ProjectKind; Settings owns connector rows; Agent owns chat rows. `quality/studio-ownership.json:snapshotSplitModules` enumerates each former symbol and its one authoritative actual definition, including pure type relationships. There is no `types` or domain compatibility barrel. Platform identity is a root module; its ledger owner matches its exact path (`platform/identity.ts`).

Project/asset/video record constructors live respectively in `projects/models/newProject.ts`, `library/models/newAssets.ts`, `video/models/newRecords.ts`. Shared production guards split into platform patch/order mechanisms and concrete Projects/Library/Video owner guards; `platform/product/scopes.ts` alone defines the fixed product table scope descriptors. `PackageError` has one neutral definition in `platform/data/packageError.ts`.

Every feature has focused tests beside its owner. Audio retains engine/MIME and real independent transaction/query tests; Agent owns topic grouping, Settings catalog UI logic, Video shot filtering, Music review wire presentation, Library asset search/tab parsing, References local parser/DOCX extraction, Memory inclusion schema validation, Projects missing-kind compatibility. The final three are existing assertion blocks extracted verbatim from root integration suites; DB/ZIP/cross-feature integration stays at root. TopicGrouping drops two type-check-proven redundant non-null operators; no assertion values change. Native suite inventory includes every feature-owned test; Vitest and Knip discover their actual paths.
